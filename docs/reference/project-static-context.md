# 项目静态上下文

> 用途：复用长期不变的项目背景与工程约束。当前进度、部署版本、阻塞、运行结果和下一步不写入本文，统一读取 `../PROJECT_SNAPSHOT.md` 并按任务路由读取唯一交付/阶段事实源。

## 项目与架构

- 应用根目录为 `/Users/yang/projects/feedback-platform`；上下文入口是上级目录的 `/Users/yang/projects/tools/context-start.sh`。
- 后端使用 Kotlin / Spring Boot，前端使用 Vue 3；仓库另含 Android SDK 与 Demo。
- MySQL 是权威事实源；Elasticsearch 与 Milvus 是可重建派生索引，不能反向覆盖权威数据。
- 外部渠道保留各自来源语义、来源记录 ID、来源时间、幂等和审计事实；分析平台默认只读，不回写来源系统。

## 固定工程规则

- Flyway 迁移只允许前向新增；已经应用的迁移禁止编辑。迁移与运维 SQL 必须保持普通 Git 文本，不得成为 LFS 指针。
- 保留用户已有工作树改动；只检查和修改任务相关路径，不清理、不覆盖、不回退无关变化。
- 在 `codex/*` 或其他任务分支开发，通过 PR 合并；不在 `main` 做常规实现提交。
- 不提交依赖、虚拟环境、构建/覆盖率/运行输出、数据库转储、临时渲染、秘密或本机配置。
- 统计与权限判断由程序和受控查询完成；模型只处理允许的已脱敏输入，不能成为权限、脱敏或统计事实源。

## 固定安全与业务约束

- 一期业务模块是四渠道数据查看与问题深度分析；四渠道为学习机反馈、Jira、质量平台、红黑榜。底层 `STATION_FEEDBACK` 渠道码保持不变。
- 飞书授权必须以已绑定的稳定用户 ID 为主键，不按姓名授权；权限调整与管理员变更必须留审计。
- 一期权限包为 `access:phase_one_workspace`，由 `PHASE_ONE_USER` 角色承载；管理员不受一期只读工作区隔离。
- 原始敏感值不得进入普通 UI、搜索、索引、AI、报表、导出或归簇。规则脱敏成功后可自动进入平台；技术失败必须失败关闭、审计并可重试。
- 受控身份与证据必须实时鉴权、填写用途、记录审计、返回 `no-store`，关闭窗口后清除前端内存；附件仍须通过完整性、恶意软件和内容审核门禁。
- 页面隐藏或删减不等于删除来源、审计、幂等、安全或附件事实。
- 问题簇按用户选择区间计算反馈数、首次和最近发生时间；不另设固定“近期反馈量”。跨渠道簇必须在同一区间至少命中两个一期渠道。

## 测试与证据分级

- 提交前运行 `tools/dev-check.sh --static`；普通代码变更运行 `--quick`；跨栈合并前运行 `--full`。
- 静态、单元、本机、Mock、降级、集成、目标环境和生产证据必须明确区分；本机或降级通过不得表述为生产集成成功。
- 浏览器交互默认禁止。确需页面目视验收时，由用户按给出的 URL 和最少步骤执行；只有用户在当回合明确授权并接受 Token 成本后才可使用浏览器工具。

2. 复用本文的静态背景，不重复读取或重新总结架构、迁移、安全、分支、测试和证据规则。
3. 只读取快照为当前任务链接的一份交付/参考文档；仅在快照明确需要更深状态、阻塞或陷阱时定向读取阶段/项目记忆。

6. 每次执行前说明：复用的静态上下文、新读取的动态信息、无需重复读取的内容。
