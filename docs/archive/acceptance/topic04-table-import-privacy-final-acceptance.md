# 专题 04：表格导入与隐私最终验收

## 结论

**PASS（实习生项目最终汇报范围）**。

表格导入已形成“文件边界—模板映射—加密暂存—分片处理—脱敏门禁—批次对账—权限控制—安全回滚”的闭环。本结论不代表生产级容量、对象存储集群或正式上线批准。

## 闭环范围

### 大文件与批次处理

- 单文件允许 1B–20MB，单工作表最多 50,000 行、200 列。
- 分片上传单片最多 5MB、最多 1,000 片，合并后仍执行 20MB 总文件校验、完整 SHA-256 校验和文件类型校验。
- 大于 5MB 的文件强制进入加密分片暂存；完成请求只持久化文件哈希和解析参数，后台 staging worker 异步组装、校验和解析，前端轮询完成后读取映射预览。
- 上传建行时每 500 行刷新并清理持久化上下文；后台每次事务只处理 500 行，批次大于 500 行时释放租约后继续领取，避免单事务承载全部数据。
- 批次完成时强制校验 `成功 + 失败 + 跳过 + 待复核 = 总行数`，不匹配则批次标记 FAILED。

### 并发与幂等

- 批次内容使用 `(source_channel, content_sha256)` 唯一约束；业务键使用渠道与来源记录号约束，并通过内容指纹和来源更新时间区分重复、旧数据与冲突。
- 后台领取使用 MySQL `FOR UPDATE SKIP LOCKED` 与两分钟租约；并发 worker 不会领取同一批次。
- 本次真实回放同时提交两个不同文件，生成两个不同批次并均独立完成；1201 行批次跨 3 个处理片完成。

### 隐私数据生命周期

- 上传原始行在数据库中使用 AES-256-GCM 加密保存，记录 nonce、tag、密钥版本和 7 天保留期。
- 映射预览仅返回再次脱敏后的内容，单元格截断至 500 字符。
- 每一行必须先通过脱敏门禁才会建立正式反馈；需要人工复核的行不进入正式反馈主表。
- 成功行处理完成后立即清空密文、nonce、tag 和密钥 ID，并记录 `raw_deleted_at`。
- 精确地址不进入质量渠道扩展表；联系方式只保留加密隔离事实和不可逆指纹，不进入普通查询结果。
- 原文查验要求 `action:inspect_masking_raw`、授权工单、用途说明、保留期有效并写入审计。

### 权限与回滚

- 修复真实上传路径未绑定细粒度权限的问题：直接上传、分片上传、合并、导入附件和映射确认现在统一要求 `action:upload_file`。
- 导入读取要求 `access:import_management`；对账导出要求 `feedback:export`。
- 普通反馈列表、详情和导出还会执行 `FIELD` 列级权限；未配置字段规则时兼容现有可见性，配置后采用白名单/拒绝规则且 `DENY` 优先。
- 普通 JIRA/质量/红黑榜导入允许具备上传权限的操作员执行；SDK 模拟导入额外限定管理员。
- 重试和回滚门禁保持明确：普通重试、POST/DELETE 回滚仅管理员；技术失败重试允许管理员/操作员，但 SDK 模拟导入仍由控制器限制为管理员。
- 回滚只允许创建后配置窗口内的 COMPLETED 批次，默认 24 小时；回滚采用正式内容软删除，保留批次对账事实。
