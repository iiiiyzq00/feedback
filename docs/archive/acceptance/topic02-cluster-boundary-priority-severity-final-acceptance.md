> 结论：PASS

## 1. 口径结论

- `S0～S4` 表示反馈影响严重度；`P1～P3` 表示人工审核处理顺序。
- 严重度可以单向影响处理优先级：S0/S1→P1，S2→P2；优先级不得反向修改严重度。
- `S4` 只允许纯正向且无故障影响；BUG/CRASH、闪退、卡死、失败等故障记录不得因渠道或模拟样本分支被赋为 S4。2026-08-04 已通过 `simulation-repair-v2` 纠正红黑榜跨渠道闪退夹具并将 S1 结果送入强制复核。
- P2 还包含已解决问题疑似复发，以及满足反馈量、有效渠道数且前两候选分差较小的竞争热点。
- P3 是其余一般边界不确定项。
- 当前治理版本为 `cluster-review-priority-v1`，竞争分差为 0.03，热点最少 2 个渠道、5 条反馈。
- SLA：P1 为 4 小时，P2 为 1 个工作日，P3 为 3 个工作日；周末与配置节假日跳过。

## 2. 边界策略

1. 产品、非允许跨域模块、问题类型、错误签名或明确症状类别冲突时，不得自动合并。
2. 仅文本相似不能自动关联；至少需要结构化画像、规范错误签名或高向量证据。
3. 错误签名一致且无竞争候选，或两项以上核心画像一致并达到高阈值时，才允许 `AUTO_HIGH`。
4. 多个候选分差不高于治理阈值时进入 `CANDIDATE` 人工审核，不生成 MAIN，不增加簇统计。
5. 已解决簇出现强复发证据时进入人工重开判断。
6. 无合格候选时保守创建新簇，避免语义相似造成错误合并。

## 3. 人工审核与生命周期

- 支持确认归入、拒绝全部候选、稍后处理、新建簇、解除主关联和复发重开。
- 所有写操作要求 UUID 幂等键、理由和期望版本；并发旧版本返回 409。
- 确认/拒绝会关闭候选；稍后处理保留 PENDING，但审核版本递增，防止旧页面覆盖。
- 合并要求产品、模块、问题类型兼容；拆分必须完整且互斥地划分全部成员。
- 合并与拆分保留旧关联、父子谱系、操作理由、操作者和审计记录，并确保每条反馈只有一个活跃 MAIN。
