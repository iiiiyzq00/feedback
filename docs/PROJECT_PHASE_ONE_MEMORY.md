- 2026-10-11 修掉上一条记录的缺陷：`FeedbackListProjectionMutationCoordinator.claimDirty` 与 `refreshIncremental` 的注解改为 `REQUIRES_NEW`（各加一处传播，逻辑与签名不变）。理由是这两处被 `@TransactionalEventListener(AFTER_COMMIT)` 调用时，外层写入事务已经提交但连接仍绑定在当前线程，默认传播会让它们挂进那个已结束的事务、自己不提交、行锁要等连接回收才释放，而确认动作走 `REQUIRES_NEW` 另开连接去等这些锁；`FeedbackListProjectionSynchronizer.refreshIncremental` 是 `@Transactional(MANDATORY)`，所以协调器必须自开事务。实测同一条写入请求响应从约 100 秒降到 1.1 秒 / 0.12 秒、请求返回时 dirty 表已为空、新行 0.5 秒内进入 ACTIVE 投影；`:backend:architectureTest` 绿，投影与站点相关 34 个测试类 126 项全过。启动期 drain 入口保留，语义收窄为「没有 XXL 调度中心时人工排空积压行」。
