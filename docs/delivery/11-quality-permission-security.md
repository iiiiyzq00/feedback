# 交付物 11：数据质量、权限与安全

## 1. 数据质量指标

| 指标 | 计算口径 |
|---|---|
| 必填完整率 | 必填字段有效行数 ÷ 总行数 |
| 主键重复率 | 重复业务键行数 ÷ 总行数 |
| 时间/枚举合法率 | 通过相应校验行数 ÷ 可校验行数 |
| 映射成功率 | 应用、模块、版本或字段映射成功数 ÷ 应映射数 |
| 脱敏通过率 | PASS 行数 ÷ 已完成脱敏行数 |
| 导入成功率 | 新增+更新+业务跳过 ÷ 总行数 |
| 疑似重复率 | 进入跨渠道候选记录数 ÷ 正式记录数 |
| 隔离数量 | 未关闭的 REVIEW_NEEDED/FAILED 安全记录数 |

数据质量按渠道和批次计算必填完整率、主键重复率、时间/枚举合法率、应用/模块/版本映射率、脱敏通过率、导入成功率、跨渠道疑似重复率和隔离数量；超过阈值触发告警。

## 2. 权限模型

| 层次 | 控制内容 |
|---|---|
| 认证 | Web Redis 不透明会话；SDK HMAC |
| API 权限 | 读取、上传、导出、编辑、报告、原文检查 |
| 行级范围 | CHANNEL、MODULE、REGION、TENANT |
| 列级范围 | FIELD 白名单或 DENY，覆盖列表、详情和导出 |
| 高风险动作 | 回滚、删除、重跑、附件/联系方式解密、原文检查 |

Web 使用 Redis 托管的随机不透明会话、角色和动作权限。浏览器 Cookie 不包含身份或权限事实，每次请求同时校验 Redis 会话、数据库用户状态和 `auth_version`；Redis 不可用时认证失败关闭。数据范围支持渠道、模块、区域、租户和 FIELD；DENY 优先。普通用户只能访问脱敏数据，导出、上传、回滚、原文检查和附件解密分别受专门权限控制。所有查询、导入、导出、人工修正和高风险操作写审计。

**TENANT 维度（2026-10-09，V245）与其余维度有三处不同，不要按同一口径理解**：

- 取值来自 `t_auth_tenant` 注册表（**封闭可枚举**，不是自由字符串）；
  账号所属租户落在 `t_auth_user.tenant_key`，数据归属的权威锚点是
  `t_application_identity.tenant_key`。
- **没有 TENANT 授权行时的默认是「只看自己租户」，不是拒绝全部**——照抄渠道维度的
  「无行即拒绝」会让迁移上线当天全部存量用户立刻看不到任何数据。
- **跨租户的失败语义是「不存在」（`FEEDBACK_NOT_FOUND`），不是「拒绝」**
  （`DATA_SCOPE_ACCESS_DENIED`）：报拒绝就等于给出一个可以探测
  「这个 ID 在别的租户里存在」的信道。
- 它由 `DataAccessScope.permitsTenant` **单独判定**，刻意不并进 `permits(...)`：
  并进去就要加一个带默认值的参数，全部现存调用点会静默变成「不检查租户」。
  **目前只有 `FeedbackAccessGuard` 调用了它**，其余行级范围调用点仍不看租户，
  未迁移清单见 `29-rca-agent-runtime.md` 第 12.7 节。

## 3. 安全与审计

SDK 使用每应用独立 HMAC 密钥、时间窗和 nonce 防重放；正文和附件在客户端加密。服务端原始信封、导入行和分片使用 AES-256-GCM 并按保留期清理。真实密钥和真实数据不得进入仓库。

- 日志、监控和异常只使用稳定错误码和安全摘要。
- 文件名、MIME、大小、哈希、URL 和存储路径均校验。
- 外部链接只允许 HTTPS 和批准来源；附件使用短时一次性授权令牌。
- 密钥通过环境或系统凭据存储注入，仓库只保存占位符。
- 单一服务或渠道异常由租约、重试、熔断和告警隔离。

## 4. 统计口径治理

SDK 是主动反馈样本，Jira 是文件快照工单，质量平台是缺陷/售后样本，红黑榜是运营评价样本。系统按渠道分别展示并标注新鲜度；合并指标明确使用原始记录或问题簇，不将不可比渠道简单相加。

详细指标见 `../reference/system-metrics-guide.md`，权限验收见 `../../../docs/archive/implementation/day7/day7-u01-u12-user-rbac.md`，隐私证明见 `09-masking-validation.md`。

## 5. 告警与处置

质量阈值按渠道、批次和指标配置，异常生成带证据的 P0–P3 告警。Jira 与其他表格渠道使用统一的导入失败率和文件新鲜度规则，不重复维护 Jira 专属同类规则；渠道差异通过阈值参数和标签表达。

告警证据包含时间窗、渠道/批次、分子分母、阈值、实际值、样本链接和数据最新时间。告警支持确认、转派、静默、解决和关闭，状态变化不反向修改来源系统。

## 6. 高风险操作控制

| 操作 | 前置控制 | 审计内容 |
|---|---|---|
| 导出 | 导出权限、行列范围、PASS 与二次脱敏 | 条件、数量、字段集、结果摘要 |
| 原文检查 | 隐私专权、理由、最小展示、短时访问 | 记录、理由、操作者、时间和结果 |
| 批次回滚/作废 | 管理权限、影响分析、并发版本检查 | 前后状态、影响数量、请求 ID |
| 附件/联系方式解密 | 独立权限、归属检查、一次性授权 | 对象、用途、授权和下载结果 |
| 用户/规则修改 | 管理权限、合法性校验 | 前后值、发布版本和操作者 |

审计记录只能包含安全元数据、标识符和摘要，不能为了“完整审计”保存原始敏感正文。

## 7. 保留、清理和事件响应

导入文件、密文暂存、附件、应用数据、审计和备份分别配置保留期。到期清理由租约任务执行并记录结果；合法保留要求暂停销毁时需有审批和期限。

发现泄漏或越权时，先阻断出口与相关凭据、保全安全审计、确定影响渠道/时间窗/字段，再清理派生索引并从 PASS 权威数据重建。事件处置不得把敏感原文复制到工单、聊天或普通日志。
