# 项目说明：七个关键问题回答

## 1. 四个渠道如何接入，为什么？

SDK 采用实时加密 API，以满足交互反馈和状态更新；Jira、质量平台、红黑榜采用只读 Excel/CSV，因为现阶段来源以文件交付且不允许回写。四渠道共享脱敏和统一模型，但保留独立适配器、批次及来源口径。

实现证据：[系统架构与四渠道数据流](04-architecture-and-channel-flows.md)、[三类表格导入](07-table-imports.md)。

## 2. 如何适配质量平台和红黑榜表头变化？

通过渠道模板、表头别名、映射推荐和版本化确认适配。完全匹配才自动处理；新增、缺失或非空未映射列进入待确认。确认后发布新模板版本，历史批次继续使用原映射快照。质量业务键生成保持不变。

实现证据：[三类表格导入](07-table-imports.md)、[字段映射与对账](08-mapping-and-reconciliation.md)。

## 3. 哪些节点脱敏？

SDK 解密后、表格预览/导入/落库前、AI/向量/第三方调用前、查询/报表/导出前。失败记录进入隔离区。

普通链路强制 `masking_status=PASS`。隐私工作台默认只展示非正文安全元数据；确需查看原文判断规则时，必须具备独立高权限、填写理由并形成审计，不能通过普通查询接口获取。

实现证据：[脱敏规则与验证](09-masking-validation.md)。

## 4. 如何证明日志、向量库和 AI 没有原始敏感数据？

使用带唯一敏感标记的模拟夹具，验证日志/审计只含安全错误和命中类型；验证隔离记录没有 AI/索引任务；验证 ES/Milvus 同步和 LLM 调用均经过 PASS 与出站隐私门禁。详见 `09-masking-validation.md`。

证明采用“带标记输入 + 各存储/出站反向检索 + 审计记录”组合，而不是只检查页面。原始导入内容如因隔离修复需要保留，须加密、限制用途和按期清理；地址、姓名等业务调用应使用脱敏值、令牌或经授权的受控流程。

## 5. 如何区分原始记录数和去重问题数？

原始记录数统计四渠道正式来源记录；去重问题数统计具有活跃 MAIN 关联且未归档的问题簇。来源记录永不因归簇物理删除。

实现证据：[AI 与归簇评估](10-ai-design-and-evaluation.md)、[指标字典](../reference/system-metrics-guide.md)。

## 6. 如何避免统计口径不一致？

看板支持按渠道独立查看，指标展示定义和新鲜度；合并指标明确使用原始记录或问题簇，不直接相加不可比渠道。红黑榜正负向、Jira 处理状态和质量缺陷分别保留来源口径。

实现证据：[数据质量、权限与安全](11-quality-permission-security.md)、[指标字典](../reference/system-metrics-guide.md)。

## 7. 渠道或 AI 不可用时如何降级？

各渠道任务、worker 和重试状态隔离，单一文件批次不影响 SDK 或其他渠道。AI 不可用时分类使用确定性规则，报告/助手使用 SQL 事实和模板文字；查询、统计和接入继续可用。外部索引可由 MySQL 权威数据重建。

实现证据：[系统架构与四渠道数据流](04-architecture-and-channel-flows.md)、[AI 设计与评估](10-ai-design-and-evaluation.md)、[现场 Demo](13-demo-runbook.md)。
