# 交付物 08：字段映射与数据对账报告

每个批次保存原文件名、文件/标准化摘要、工作表、模板 ID、字段映射版本/快照、枚举映射组合版本/快照、总行数、新增、更新、跳过、失败、待复核和对账状态。行级保存行指纹、业务键哈希、安全错误和转换事实。

## 1. 公共字段映射

| 统一字段 | Jira 示例 | 质量平台示例 | 红黑榜示例 |
|---|---|---|---|
| `source_record_id` | Issue Key | 问题编号/组合键 | 来源记录 ID |
| `title` | Summary | 问题标题 | 评价标题 |
| `description` | 描述/评论摘要 | 故障描述 | 问题或表扬描述 |
| `function_module` | Component | 应用模块 | 所属应用/模块 |
| `severity_level` | Priority 映射 | 严重程度 | 影响等级 |
| `processing_status` | Jira 状态 | 缺陷状态 | 来源状态/默认开放 |
| `source_event_time` | 创建时间 | 商返申请/业务时间 | 发布时间 |
| `source_update_time` | 更新时间 | 来源更新时间 | 更新时间 |

负责人、报告人、账号、设备和来源人员字段只能保存脱敏标识、哈希或安全文本。来源口径字段和统一字段分别保存，统一转换不能覆盖来源事实。

## 2. 映射版本

- 模板定义允许表头、目标字段、必填字段和版本。
- 批次保存模板 ID、版本及实际映射 JSON，保证以后可复现。
- 枚举映射按渠道+字段加载，但在批次开始处理前合并为一个不可变快照；组合版本由渠道和规范化后完整内容计算，目标值必须属于允许集合。
- 人工修正记录旧值、新值、原因、操作者以及该行真实使用的字段映射版本和枚举组合版本，禁止写固定占位版本。
- 失败或部分成功批次重新确认时，映射快照未变化才可沿用原版本；任何字段映射变化都必须发布并绑定新模板版本。

对账恒等式为：

```text
新增 + 更新 + 跳过 + 失败 + 待复核 = 总行数
```

不成立时批次标记失败。后台支持失败行查看、技术重试、映射确认、批次重放、权限受控回滚及 XLSX 对账导出。导出只包含脱敏数据，并再次执行出站隐私门禁和 FIELD 权限。

## 3. 对账报告内容

正式 XLSX 至少包含批次 ID、渠道、状态、开始/完成时间、文件摘要、总行数、新增、更新、重复跳过、旧快照跳过、失败、待复核、附件任务和对账结论。失败行只包含行号、错误码、安全摘要和修复建议。

| 指标 | 演示值 |
|---|---:|
| 总行数 | 1,000 |
| 新增 | 700 |
| 更新 | 180 |
| 重复/旧快照跳过 | 100 |
| 失败 | 10 |
| 待复核 | 10 |
| 对账 | `MATCHED` |

演示值满足 `700 + 180 + 100 + 10 + 10 = 1,000`；它只解释口径，真实验收以批次数据库事实和实际导出文件为准。

## 4. 导入前后及回滚核验

导入前记录渠道正式数量和业务键集合；导入后按批次关联来源记录并核对分类。回滚后正式内容不可见，但批次、行级对账和审计仍保留，从而证明回滚不是删除验收证据。

模拟验收数据位于 `data/test-fixtures/full-system-20260805/`，其中 `manifest.json` 和 `expected-results.csv` 给出预期数量；专项报告见 `../archive/acceptance/topic04-table-import-privacy-final-acceptance.md` 和 `../../../docs/archive/implementation/day5/day5-i01-i12-import-management-governance.md`。

## 5. 映射变更流程

1. 上传后读取工作表、规范化表头并生成候选映射。
2. 未知、歧义、缺失必填或非空未映射列必须人工确认。
3. 确认时冻结字段映射快照、转换函数版本和完整枚举字典快照。
4. 新表头发布新模板版本，历史批次继续引用旧快照。
5. 人工修正只更新平台标准字段并记录前值、后值、理由和操作者，不修改来源口径；技术重试复用原快照，映射变更发布新版本。

## 6. 行级处置定义

- `新增`：业务键首次形成正式来源记录。
- `更新`：相同业务键且来源更新快照获胜。
- `跳过`：完全重复、旧快照或按明确业务规则忽略。
- `失败`：格式、业务或技术错误，未形成正式记录。
- `待复核`：需要映射或隐私人工判断，不能进入普通出口。

非 PASS 隔离行必须归入明确处置，不能从总数中消失。导出的对账文件本身也执行字段权限和二次脱敏，未经脱敏的失败正文不得进入报告。

## 7. 对账报告签署项

| 项目 | 记录内容 |
|---|---|
| 身份 | 渠道、批次 ID、文件名/摘要、工作表、数据日期 |
| 版本 | 模板、映射、枚举、标准化、脱敏规则版本 |
| 数量 | 总行、新增、更新、跳过、失败、待复核、正式记录 |
| 质量 | 完整、重复、日期/枚举合法、映射、脱敏通过率 |
| 差异 | 错误码分布、旧快照、重复键、未映射字段 |
| 证据 | 开始/结束时间、操作者、重试链、回滚/作废状态 |
